# temt 概要

temt は、使い捨ての EC2 インスタンスにサービスを載せる。使うときだけ立てて、
使い終わったら畳む。これによりコストを下げ、同時にセキュリティを高める。

この文書は、設計で選択肢が分かれたときに何を優先するかを定める。具体的な設計は
[design.md](design.md) に書き、判断の理由は、手順だけでは意図が読めないところに
だけ短く書く。

## 前提

- 操作は Linux（Ubuntu 24.04 / 26.04）から行う。WSL2 でもよい。
- 1 つのサービスは 1 つの設定ファイルで定義し、インスタンスを 1 台持つ。同じ用途を
  設定違いで複数立てるときは、設定ファイルを写して別のサービスにする。

## 原則

1. **使っていない間は存在しない。** 誰も使っていなければインスタンスは自分から
   終了する。無い間は費用も攻撃面も無い。
2. **毎回、新しく作る。** インスタンスはイメージから起動し、終了とともに消える。
   残すべきものはインスタンスの外に置く。ただし、作業を中断して続きから使うときに
   限り、インスタンスを止めておいて再開することもできる。止めている間も、ディスクは
   残り、その費用はかかる。
3. **小さく作る。** サービスが数個、という規模で楽な方を選ぶ。必要になるまで作らず、
   既に使っている道具で済ませる。
4. **自動化できるところは自動化する。** 繰り返す操作は利用者の手順にせず、
   仕組みに持たせる。
5. **利便性を失わない範囲でセキュリティを強化する。** 使い方が変わらないなら、
   より安全な側を採る。どこまで強めるかは個々の設計で決める。
