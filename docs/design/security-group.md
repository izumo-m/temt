# セキュリティグループ

`apply` の手順 6 で揃え、`destroy` の手順 4 で消す。名前は `<名前>`。受信規則の
定義を見る・直すのは `sg` のコマンドで、AWS には書かない
（[design.md](../design.md#sg-のコマンド)）。

## 揃える

設定ファイルの `SubnetId` が属する VPC に作り、2 つのタグ（`Name`、
`temt:service`）を付ける。既にあれば、無いタグを足し、値の違うタグを直す。他の
タグには触らない。別の VPC に同じ名前のセキュリティグループがあっても、エラーに
せず、そのまま残す。

## 受信規則

受信規則は設定ファイルの `[[security-group.ingress]]`（プロトコル、ポートの範囲、
送信元の CIDR、説明）で定義し、`apply` が AWS 側をそれに揃える。定義が無ければ
受信規則は無く、ログインは Session Manager 経由だけになる。送信規則には触れない。

プロトコルは `tcp`、`udp`、`icmp` の 3 つである。`icmp` はポートを持たず、ICMP の
すべての種類を許す。送信元が IPv6 の CIDR なら、AWS には `icmpv6` として渡す。

規則は、プロトコル、ポートの範囲、送信元の CIDR の組で見分ける。AWS も同じ組で
規則を見分け、説明はその規則に 1 つだけ付く。`icmp` のポートの範囲は、AWS の
表し方（`-1` から `-1`）で比べる。

揃え方は差分で行う。`describe-security-group-rules` でセキュリティグループの受信
規則を 1 つずつ読み、定義と比べて、次の順に操作する。

1. 定義にあって AWS に無い規則を、`authorize-security-group-ingress` でまとめて
   足す。
2. 両方にあって説明だけが違う規則は、`update-security-group-rule-descriptions-ingress`
   で説明を直す。消して足し直すと、その間は通らなくなるからである。
3. AWS にあって定義に無い規則を、`revoke-security-group-ingress` に規則の ID を
   渡してまとめて消す。temt が扱わない種類の規則（他のセキュリティグループの参照、
   プレフィックスリスト、`tcp`・`udp`・`icmp`・`icmpv6` 以外のプロトコル、ICMP の
   種類を絞った規則）も、定義に無いのでここで消える。

足してから消すので、揃えている間も、定義にある規則は通り続ける。違いが無ければ
何もしない。足した規則、説明を直した規則、消した規則を 1 つ 1 行で知らせる。足す間は
規則が消す分だけ多くなるので、セキュリティグループあたりの受信規則の上限（既定では
60）に近いところで多くを入れ替えると、足すところで止まる。そのときは、消す規則を
先に定義から外して `apply` し、足す規則を分けて `apply` する。

## グローバル IP アドレス

`sg add` と `sg remove` は、CIDR を省くと手元のグローバル IP アドレスを調べて CIDR に
する（[design.md](../design.md#sg-のコマンド)）。IPv4 と IPv6 を別々に調べる。
グローバル IP アドレスは、インターネットから見た手元のアドレスである。VPN を
通していれば、VPN の出口のアドレスになる。

| 種類 | 問い合わせ先 | CIDR |
| --- | --- | --- |
| IPv4 | `https://checkip.amazonaws.com` | `/32` |
| IPv6 | `https://api6.ipify.org` | `/64` |

- どちらのホストも、その種類のアドレスしか DNS に持たないので、問い合わせは必ず
  その種類で行き、返るのはその種類のグローバル IP アドレスである。
- 応答の本文を IP アドレスとして読み、種類が違えば取れなかったものとする。ゾーン ID
  の付いたアドレスと、ループバック、未指定、リンクローカル、マルチキャストの
  アドレスも、取れなかったものとする。
  接続と読み取りの待ちは、それぞれ 5 秒までとする。名前の解決には締め切りを置か
  ないので、1 回の問い合わせ全体が 5 秒に収まるとは限らない。
- IPv6 を `/64` にするのは、多くの OS が外への接続に一時アドレス（プライバシー
  拡張で 1 日ほどで入れ替わるアドレス）を使い、`/128` ではすぐ通らなくなるから
  である。`/64` は LAN 1 つ分で、IPv4 で NAT の後ろの機器を 1 つのアドレスでまとめて
  許すのと同じ範囲になる。
- サブネットに IPv6 の CIDR があるかどうかは見ない。AWS を呼ばずに済ませるためで
  ある。IPv6 の規則は、インスタンスに IPv6 アドレスが付かなければ効かないが、害も
  無い。
- 取れた種類だけを使い、取れなかった種類は理由を 1 行で知らせる。どちらも取れなければ
  エラーにして終了する。

## VPC の変更

`SubnetId` を別の VPC のサブネットに変えたときは、`apply` が新しい VPC に
セキュリティグループを用意し、起動テンプレートがそれを指す。動いているインスタンスは
古いセキュリティグループのまま動き続け、次の `start` から新しい VPC で立つ。古い
VPC に残ったセキュリティグループは `destroy` が消す。

## 消す

`destroy` は、リージョンの中で名前が `<名前>` のものを、VPC を問わずすべて消す。
削除が `DependencyViolation` で失敗したら、終了したインスタンスのネットワーク
インターフェースが外れるまで、締め切り（[instance.md](instance.md#待ち合わせ)）まで
繰り返す。
