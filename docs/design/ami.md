# AMI

`bake` がサービスのインスタンスから作る。起動テンプレートの `ImageId` は設定
ファイルの `ImageId` から来る。名前とタグの規則は [design.md](../design.md#名前)
にある。

## 作る

`bake` の手順 6（[design.md](../design.md#クライアントのコマンド)）。停止した
インスタンスから `create-image` で作る。

- 名前は `temt-<svc>-<YYMMDDHHMM>`。時刻は `create-image` を呼ぶときのクライアントの
  ローカル時刻である。
- AMI とスナップショットに、`TagSpecifications` で `Name=<AMI の名前>` と
  `temt:service=<svc>` を付ける。

`bake` はインスタンスの中身に手を加えず、ありのままを焼く。焼く前に片づけることは
しない。たとえば、前のキーペアで足された `~/.ssh/authorized_keys` の行も、焼いた
AMI から起動したインスタンスにそのまま残る。これは求める振る舞いであり、変えない。

AMI の名前はアカウントとリージョンの中で一意でなければならない。同じサービスを同じ
分のうちに 2 回焼くと、2 回目の `create-image` が名前の重複で失敗する。そのときは、
1 分おいてやり直すよう告げて終了する。

`bake` は古い AMI を消さない。消すのは `ami prune` と `ami delete` である。`ami prune`
は、どの起動テンプレートのどのバージョンからも指されていない AMI の登録を解除し、
スナップショットも消す。`ami delete` は、ID か名前で指した 1 つを消す
（[design.md](../design.md#クライアントのコマンド) の `ami prune` と `ami delete`）。
`bake` は AMI が `available` になってからテンプレートを向けるので、その短い間の
AMI はどのテンプレートからも指されない。`ami prune` は、AMI を 1 つ消すたびに
そのサービスのロックを取ってテンプレートを読み直すので、同じマシンから打った
`bake` の AMI は消さない。

## 選ぶ

`ImageId` が無いか空なら、`apply` の手順 2 で選び、設定ファイルに書く。自分の
アカウントの AMI から、そのサービスの `temt:service=<svc>` のタグを持ち状態が
`available` のものを探し、`CreationDate` が最も新しいものを使い、その名前を書く。
1 つも無ければ、Canonical が公開している SSM のパブリックパラメータ
`/aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id`
から Ubuntu 24.04 の AMI ID を得て、ID を書く。公開 AMI は自分のアカウントの
ものではないので、名前では指せない。

`ImageId` が書かれていれば、その値をそのまま使い、選び直さない。最新の AMI に
選び直すには、行を消すか空にして `apply` する。選び直す先は、そのサービスから
焼いた AMI（無ければ Ubuntu 24.04）である。他のサービスから焼いた AMI を
使うには、その名前か ID を書く。設定ファイルを写して別のサービスを作ると、
`ImageId` も写るので、同じ AMI から起動する。写した先で行を消すと、写した先の
サービスから焼いた AMI から選び直す。

そのサービスから焼いた AMI は、名前の前方一致ではなく `temt:service` タグで
見分ける。サービス `dev` の AMI を名前 `temt-dev-*` で探すと、サービス `dev-main` の
AMI も拾うからである。

## 名前で指す

`ImageId` には AMI の ID も名前も書ける。値が `ami-` に続けて小文字の 16 進数
8 桁か 17 桁の形なら ID、それ以外は名前として扱う。

- 名前は、自分のアカウントの AMI からだけ探す（`describe-images` の
  `Owners=self` と `name` の絞り込み）。名前はアカウントとリージョンの中で一意だが、
  持ち主をまたぐと重なることがあるからである。
- 絞り込みの値は `*` と `?` を展開するので、これらを含む値は誤りとする。
- 登録を解除した AMI は、解除の直後はしばらく `deregistered` の状態で見える。これは
  無いものとして扱う。
- 使える状態は `available` と `pending` である。手で書いた `ImageId` が、作っている
  途中の AMI を指していても受け付ける。起動テンプレートは、起動するまで AMI を
  使わないからである。
- 起動テンプレートの `ImageId` には ID しか入らないので、`apply` の手順 4 が名前から
  ID を引く。
- `apply` の手順 4 は、ID で書かれたときも AMI を引き、使える状態であることを
  確かめる。名前でも ID でも、無いか使えなければ、行を消して選び直すよう告げて
  止まる。登録解除された AMI や、別のアカウントの AMI を指しているときである。
- `bake` の手順 3 も、ID で書かれたときを含めて AMI を引き、その ID をテンプレートと
  比べる。使える AMI が無ければ、違う項目として `apply` を促す。
